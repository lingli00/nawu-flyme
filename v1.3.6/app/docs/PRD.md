## 1. 产品目标

把「纳物」这套**物品与消费复盘**方法论装进手机：用户随手记下一笔支出时，立刻给它打上「归 / 需 / 否」的价值判断，并把买过的物品折算成每日成本与使用次数，从而在月底能一眼看清「钱花在哪、花得值不值」。App 端不新增业务后端接口，沿用现有 PHP 后端做**账号认证 + 云端快照备份**，业务数据（生活流 / 物品 / 订阅）全部本地存储并在关键时刻整体快照上云，保证弱网、内网、离线场景都能用。

**三个正交目标**
1. **连得上**：让用户自己填的任意服务器（http/https、带端口、内网 IP）都能被探测、校验、保存、切换，连接状态始终可见可 diagnose。
2. **记得快**：把「记一笔」的路径压缩到 5 秒以内（AI 一句话记账 + 手动三字段快记），并强制/引导完成「归 / 需 / 否」判断。
3. **看得懂**：概览与报表用最少的数据讲清「本月花了多少、结构如何、归需否占比、物品每日成本、订阅即将续费」，不做图表堆砌。

## 2. 用户故事

| ID | 用户故事 |
| --- | --- |
| US-1 | 作为**首次打开 App 的新用户**，我希望启动后立刻被引导填写服务器地址、邮箱和密码，并在点击「测试连接」后马上知道连不连得上，这样我不需要猜后端在哪、也不需要看文档。 |

| US-4 | 作为**每天消费的普通人**，我希望点底部中间的「记一笔」，用一句话（“今天早上吃了油条包子花了30，然后坐火车花了60去桐柏”）自动拆成两条带分类和金额的记录，我只需确认一下归类再点保存，这样记账不再是个负担。 |
| US-5 | 作为**想认真复盘的人**，我希望每一笔支出都能打上「归 / 需 / 否」的判断，并在报表里看到三类各自的占比和金额，这样我能回答"这个月有多少钱是白花的"。 |
| US-6 | 作为**买了贵价物品的人**，我希望把物品、价格、附加费用、目标每日成本记下来，并随使用次数累加看到「已用 X 次 / 单次成本 Y 元 / 日均 Z 元」，这样我能判断这东西买得值不值。 |

| US-9 | 作为**没有邮箱验证码收不到的人**，我希望注册流程尽可能简单（邮箱+密码即可，验证失败也能继续用），这样我能先用起来（注：是否强制验证码取决于服务端 `requireVerified` 配置，App 做自适应流程，见 §9 Q3）。 |

优先级定义：**P0 = 必须（缺了不能发布）｜P1 = 应该有（影响体验完整性）｜P2 = 锦上添花（可放到 v0.2）**

| A-04 | 服务器 | 多服务器管理 | 保存多套配置（别名、地址、备注），列表展示、设为默认、编辑、删除（删除前二次确认）、长按/侧滑置顶。 | P0 |
| A-05 | 服务器 | 服务器切换 | 切换后清空旧 token、用新地址重新探测；若当前已有登录态且新服务器可用，提示需重新登录。 | P0 |
| A-06 | 账号 | 登录（含未验证分支） | `POST /api/auth/login`（email + password）；成功保存 token + user；记住登录状态（默认勾选）。若返回 **403「邮箱尚未验证」**，不报错，改为引导用户完成验证（展开验证码输入 + 发送验证码按钮，验证通过后自动重试登录）。 | P0 |
| A-07 | 账号 | 注册（自适应流程） | `POST /api/auth/register`。**默认只提交邮箱 + 密码 + 确认密码**（密码 ≥6 位）；后端**注册成功直接返回 token，等于自动登录**，无需再跳登录页。仅当后端返回 400 且错误信息含「验证/验证码」时（服务端 `requireVerified=true`），才**就地展开验证码步骤**并提示先点「发送验证码」。 | P0 |
| A-08 | 账号 | 登录态保持与自动校验 | App 启动/切前台时用本地 token 调 `GET /api/auth/me` 校验；通过则直进首页，失败则回登录页并保留服务器配置。 | P0 |
| A-09 | 账号 | 忘记密码（验证码重置） | `POST /api/auth/send-code` + `POST /api/auth/reset`；60s 倒计时重发。 | P1 |
| A-10 | 账号 | 修改密码 | `POST /api/auth/changepassword`（旧密码 + 新密码）。 | P1 |
| A-11 | 账号 | 退出登录 | `POST /api/auth/logout` + 清 token；**不清本地业务数据**，弹窗询问"是否先备份"。 | P0 |
| A-12 | 账号 | 站点设置（**需登录**） | `GET /api/settings` **有登录校验，未登录返回 401**，且返回体 `{ok, settings:{...}}` **不含站点名/Logo 字段**（仅 smtpConfigured 之类的开关）。因此：**引导页/登录页一律使用固定品牌名「纳物 NaWu」+ 内置 Logo，不调此接口**；本项改为**登录成功后**才拉取（**需登录后调用，未登录不可用**，见 R9），仅用于展示服务器能力开关（如"该服务器已配置邮件"），失败静默忽略。 | P2 |
| A-13 | 连接 | 全局连接状态条 | 顶部细条/胶囊：`在线(绿) / 离线(灰) / 认证已过期(黄) / 服务器不可达(红)`；点击可跳转服务器管理并重新探测。 | P0 |

| D-07 | 订阅 | 归档状态的备份兼容性 | ⚠ 归档标记是 **App 端私有扩展，Web 版不认识**。存储位置建议放 **备份 payload 的 `settings.archivedSubIds: string[]`**（而非给 `Subscription` 加 `archivedAt` 字段），理由是 `settings` 会被 Web 端整体回写，抗丢失能力更强；由架构师确认 Web 端是否会保留未知键，若会丢则回退字段方案。**无论采用哪种方案，P21 恢复成功后必须提示用户**（见下方文案）。 | P2 |

**D-07 恢复提示文案（统一口径，P21 恢复成功 Toast，3.5s）**

> 已恢复 N 条记录（备份时间 2026-10-05 14:20）。
> 注：订阅的「停用」状态不会随备份保存，如有需要请重新停用。

- 仅当本次恢复的快照中**存在订阅记录**时才追加第二行；无订阅则不显示，避免无意义打扰。
- 文案不得写成"恢复失败"或"部分失败"，恢复本身是完整成功的。

## 6. 与后端接口映射表

> 统一约定：所有请求由 `httpClient` 发出（CapacitorHttp 优先），带 `Authorization: Bearer <token>`（除 health / login / register / send-code / reset；**`settings` 需登录，不在免鉴权之列**）；统一超时 15s（health 探测 8s）；统一错误归一化为 `{kind: 'network'|'timeout'|'http'|'auth'|'parse', status?, message}`。

| 接口 | 方法 | 触发页面 / 时机 | App 侧行为 |
| --- | --- | --- | --- |
| `/api/health` | GET | P01 引导测试连接、P05/P06 重新探测、App 切前台、切换服务器 | 成功→绿点；失败→分「不可达/超时/接口异常」三态 |
| `/api/settings` | GET | **仅登录成功后**（P20 我的），P01/P02 不调用 | ⚠ **需登录，未登录 401**；返回 `{ok, settings:{...}}` 且**无站点名/Logo 字段**，仅用于展示服务器能力开关。失败静默。引导页/登录页品牌区用固定文案 |
| `/api/auth/login` | POST | P02 登录 | 存 token + user 到 Preferences；勾"记住我"则持久化；**403「邮箱尚未验证」→ 内联展开验证码区，验证通过后自动重试登录** |
| `/api/auth/register` | POST | P03 注册 | ⚠ **成功即返回 token，等于自动登录，直接进首页**；密码 ≥6 位；仅当返回 400 且 error 含「验证」时才展开验证码步骤；失败文案透传后端 error |
| `/api/auth/send-code` | POST | P03（条件触发）/ P02 未验证分支 / P04 忘记密码 | 60s 倒计时 |
| `/api/auth/reset` | POST | P04 | 成功后跳登录并预填邮箱 |
| `/api/auth/me` | GET | App 启动恢复登录态、P20 我的、切前台 | 200→刷新用户；401→标记"认证过期"，跳登录但保留本地数据 |
| `/api/auth/logout` | POST | P20 退出登录 | 清 token，保留本地业务数据 |
| `/api/auth/changepassword` | POST | P23 | 成功后提示重新登录 |
| `/api/user/backups` | GET | P21 备份列表 | ⚠ 返回体字段是 **`rows`**：`{ok:true, rows:[{id,label,item_count,bytes,device,created_at}]}`。展示 label / item_count / bytes / created_at |

| `/api/user/backups/:id` | GET | P21 恢复 | ⚠ **`payload` 可能是 JSON 对象也可能是字符串**，必须两种兼容后再写入本地；二次确认后整体覆盖本地 |
| `/api/user/backups/:id` | **DELETE** | P21 删除备份（**首选**） | 提示"服务端仅保留最近 3 份" |
| `/api/sync/list` | GET | P21（兼容旧协议，可选） | 与 backups 的 `rows` 合并去重 |

## 7. 风险与约束

### R1（硬约束）后端完全没有 CORS，WebView 内 fetch 必被拦截

- 现象：`OPTIONS` 预检返回 404，PHP 代码无任何跨域响应头。
- 影响：App 是 Capacitor WebView，页面源为 `http://localhost`（或 `capacitor://localhost`），跨域请求会被 Chromium 的同源策略拦掉，**常规 `fetch` / `axios` 全部失效**。
- **强制方案**：网络层统一走 `@capacitor/core` 的 **`CapacitorHttp`**（原生层发请求，不受同源策略限制）。
  - 注意 `CapacitorHttp` 与 `fetch` 的差异：请求头/响应结构不同、不自动带 cookie、`Content-Type` 需显式设置、返回体可能已被解析为对象也可能是字符串（需 `dataType: 'json'` 或手动 parse）。
  - 需在 `capacitor.config.ts` 中确认 `android.allowMixedContent`（http 明文）与 `server.androidScheme`；Android 9+ 默认禁止明文 HTTP，必须配置 `android:usesCleartextTraffic="true"` 或 `networkSecurityConfig`，否则**内网 http 地址（如 `http://192.168.1.100:3030`）一律失败**。
- 兜底：浏览器 `npm run dev` 调试时，`CapacitorHttp` 不可用 → 走 Vite `server.proxy` 把 `/api` 代理到目标地址（dev-only，通过环境变量 `VITE_DEV_PROXY_TARGET` 配置）。
- 验收标准：**真机上用 http 内网地址能登录成功**；这一步不过，后面全部功能都不可用，定为最高优先级技术验证项（架构阶段第一天就要打通）。

### R2（硬约束）本机无 JDK / Android SDK / Gradle，无法在本机编译 APK

- 影响：本轮交付**只能交付可运行的源码 + Web 可跑版本**，不包含已签名的 APK 文件。
- 应对：
  1. 项目必须 `npm run dev` 在浏览器完整可跑（走 Vite 代理），用于功能验证与 UI 验收。
  2. 仓库内附 **一键构建脚本**（`scripts/build-android.sh` / `.bat`），依次执行：`npm i && npm run build && npx cap sync android && cd android && ./gradlew assembleDebug`，产出 `android/app/build/outputs/apk/debug/app-debug.apk`。
  3. `docs/BUILD.md` 写明前置依赖（JDK 17、Android SDK Platform 34、Build-Tools、`ANDROID_HOME` 环境变量），以及首次需 `npx cap add android`。
  4. 已生成的 `android/` 目录（若在本机通过 `cap add` 生成）一并提交，减少用户侧步骤。
- 验收标准：用户在装有 Android Studio 的机器上执行脚本后能得到可安装 APK。

### R3（硬约束）服务器地址由用户自填，形态不可控

- 场景：`http://` / `https://`、带端口、纯 IP、内网域名、自签证书、末尾多斜杠、复制时带路径。
- 应对：
  1. 输入时做**归一化**（补协议、去尾斜杠、去路径前缀）与**格式校验**（不阻塞提交，仅提示）。
  2. 探测必须区分三类错误并给出可操作文案：
     - 地址不合法 → 「地址格式不正确，示例：`http://192.168.1.10:3030`」
     - 连不上（超时/DNS/拒绝）→ 「无法连接到服务器，请检查地址、端口与网络（是否在同一个局域网/VPN 内）」
     - 连通但接口异常（非 200 / 非预期 JSON）→ 「服务器已连通，但接口返回异常（HTTP xxx），请确认这是纳物服务端」
  3. https 自签证书失败时，给出「证书不受信任」专项提示（Capacitor 侧需评估是否允许跳过校验，**默认不允许**，仅提示）。
  4. 保存服务器配置与 token 用 `@capacitor/preferences`（App 私有存储），**不明文日志文件输出 token/密码**。

### R4 业务数据没有服务端 CRUD，跨设备一致性弱

- 影响：物品/生活流/订阅只在本地；换机或清缓存会丢；多设备无法实时同步。
- 应对：P0 就把「备份/恢复」做成一级入口（P21），并在退出登录、恢复前强制提醒备份；P1 做自动备份（G-06）。
- 需在 UI 上明确告知用户「数据优先存在本机，备份才会上云」，避免误解。

### R5（硬约束）服务端备份只保留最近 3 份

- 现象：服务端写入备份后会执行 `trimBackups` 裁剪，**只保留最近 3 份**，更早的快照被自动删除。
- 影响：自动备份频繁会挤掉用户重要的历史快照。
- 应对：备份列表显式标注「服务端仅保留最近 3 份」；**自动备份必须 24 小时节流**（G-06：距上次备份 > 24h 才静默上传）；P2 提供本地导出 JSON 作为长期归档。

### R6 AI 能力依赖用户自配 Endpoint/Key

- 影响：多数用户不会配置，AI 入口会"没用"。
- 应对：E-03 本地规则兜底必须**足够强**（分类关键词 + 金额正则 + 分句，参照 Web 版已有实现），保证不配置也能一句话记 1–2 条；AI 配置页提供「测试连接」。

### R7 深色模式与对比度

- 三色语义色（归/需/否）在深色下需单独校验对比度，避免不可读；emoji 在部分 Android 机型渲染差异需做兜底字形。

### R8 包体积与首屏

- 不引入 ECharts / MUI 全量；图表自绘 SVG，组件按需；目标 debug APK < 25MB，冷启动（本地 hydrate）< 1.5s。

### R9（硬约束）`GET /api/settings` 需登录且不含站点信息 → 品牌名必须在客户端写死

- 现象：该接口位于后端需鉴权分支，**未登录调用返回 401**；且返回体 `{ok, settings:{...}}` 中**没有站点名 / Logo 字段**（只有 `smtpConfigured` 之类的能力开关）。
- 影响：**「首次启动、尚未登录」场景下拿不到任何品牌信息**，引导页无法用它做品牌展示（原设想 A-12 不成立）。
- 应对（已拍板）：
  1. **P01 服务器配置引导页不请求任何站点信息**，直接展示固定品牌名 **「纳物 NaWu」**（副标题「物品与消费复盘」+ 内置 Logo），品牌文案写死在客户端。
  2. **A-12 降级为 P2**，改为「登录成功后才拉取站点/服务信息用于展示」，仅用于展示服务器能力开关（如"该服务器已配置邮件"），调用失败静默忽略。
- 验收标准：未登录状态下 App 不发起 `/api/settings` 请求；引导页品牌区正常渲染。

### R10 注册是否强制邮箱验证码由服务端配置决定 → App 必须自适应

- 现象：是否校验 `code` 取决于服务端 `requireVerified` 配置（不同服务器可能不同），App 无法预知。
- 影响：把验证码框写死成必填会导致部分服务器注册失败；反之写死不填则在强制验证的服务器上注册不了。
- 应对：注册/登录一律做成**自适应流程**——先提交邮箱 + 密码；仅当后端返回 400 且错误信息含「验证/验证码」（即服务端 `requireVerified=true`）时，才**就地展开验证码步骤**并提示先点「发送验证码」。登录遇 403「邮箱尚未验证」同理，内联展开验证区，验证通过后自动重试登录。
- 影响范围：A-06、A-07、P02、P03。

**云端备份快照 payload**（POST `/api/user/backups`）

```json
{
  "payload": {
    "collections": { "goods": [], "subscriptions": [], "bills": [], "valueRecords": [],
      "moods": [], "times": [], "wishlist": [], "cooldowns": [], "categories": [],
      "usageRecords": [], "reminders": [], "walls": [] },
    "settings": {}, "count": 0, "app": "guifou-web", "version": 1, "exportedAt": "ISO"
  },
  "label": "手动备份", "item_count": 0, "device": "Android/厂商型号"
}
```

> **`app` 字段已拍板固定写 `"guifou-web"`**（不要写 `guifou-android`）：保证 App 与 Web 版快照可互相恢复，也避免服务端若按 `app` 过滤导致恢复失败。

**备份恢复时的兼容性要求（后端源码核对结论）**
1. 列表接口读 **`rows`** 字段，不要读 `backups`。
2. 详情接口的 **`payload` 可能是对象也可能是字符串**（后端 `json_decode` 失败时原样返回字符串），必须统一做 `typeof payload === 'string' ? JSON.parse(payload) : payload` 后再使用。
3. 删除优先 `DELETE /api/user/backups/:id`，失败回退 `POST /api/sync/delete`。

## 10. 建议技术栈与工程约定

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 容器 | Capacitor 7 | 复用 React Web 代码产出真原生 APK；`CapacitorHttp` 绕开 CORS（R1） |
| 框架 | React 18 + TypeScript + Vite | 与 Web 版同源，组件/工具函数可复用；Vite dev 代理用于浏览器调试 |
| 样式 | Tailwind CSS + CSS 变量令牌 | 令牌与 Web 版一一对应（§5.1），改主题只换变量；Tailwind 控制体积 |
| 状态 | Zustand | 与 Web 版一致，迁移成本低；配合 persist 中间件落 Preferences |
| 存储 | `@capacitor/preferences` + 单文件 JSON 快照 | 数据量小（万级记录内），JSON 足够；预留 Repository 接口便于 P1 换 SQLite |
| 网络 | 自研 `httpClient`（CapacitorHttp → fetch → dev 代理 三级降级） | 唯一的 R1 解法，必须集中封装，禁止组件里裸调 |
| 图表 | 自绘 SVG（环形/柱状/堆叠条） | 控制包体积，需求里的图表都很简单 |
| 导航 | React Router v6（Hash 路由，兼容 file:// 场景） + 原生返回键桥接 | 简单可控 |
| 通知 | `@capacitor/local-notifications` | 订阅续费 / 保修提醒（P1/P2） |
| 图标 | Emoji（分类）+ 少量内联 SVG（导航/操作） | 与 Web 版一致，零依赖 |

**工程约定**
1. `src/api/` 只放后端接口定义；`src/ai/` 放 LLM 与本地规则解析；两者不得混用 httpClient（AI 直连第三方）。
2. 所有金额用 `number`（元），展示层统一 `formatMoney(amount, currency)`；汇率在设置里手动维护（P1）。
3. 日期统一 `YYYY-MM-DD` 字符串 + `dayjs` 处理；时区固定设备本地。
4. 所有列表必须实现空/加载/错误三态（H-02），缺一不可验收。
5. 提交前 `npm run build` 必须通过；真机验证清单见 `docs/BUILD.md`。
