# 纳物 NaWu · 编译部署与迭代手册

> 对象：这份工程的使用者（你自己 / 你的开发同学）。
> 目标：从这台机器从零开始，**能跑、能打包、能部署、能持续升级**。

---

## 零、先理解这套工程的形状

纳物是「**一套 React 源码 → 两个产物**」：

```
                    app/src/  (唯一前端源码)
                         │
          npm run build  │  →  app/dist/
                         │
        ┌────────────────┴────────────────┐
        ▼                                 ▼
  ① App 端：npx cap sync android      ② 网页版：同步到 server/
     → android/app/src/main/assets      → server/assets/*.js|css
     → gradlew assembleRelease          → server/app/spa-m.html 入口
     → nawu-vX.Y.Z.apk                  → 手机网页版 + PC 网页版
```

- **App 端**：Capacitor 原生壳加载 `dist/`（相对路径 `./assets/...`）
- **服务端**：Nginx 直接托管 `server/`，SPA 壳是 `server/app/spa-m.html`（绝对路径 `/assets/...`）
- 服务端**不存前端源码**，它的 `assets/` 就是从 `app/dist/` 拷过来的。

> ⚠️ **最容易踩的坑**：改了 `app/src` 只重打了 APK，忘了同步 `server/assets/`，
> 结果网页版还是旧界面、版本号也对不上。
> 用 `node tools/sync-web-to-server.mjs` 一条命令搞定（见第五节）。

## 一、环境准备

### 1.1 做前端 / 网页版（必需）

| 工具 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 20（推荐 22 LTS） | `node -v` |
| npm | 随 Node | `npm -v` |

### 1.2 打 Android 包（需要时）

| 工具 | 版本 | 说明 |
|---|---|---|
| JDK | **17** | Capacitor 7 + AGP 8 的要求；JDK 21 亦可（CI 用的就是 21） |
| Android SDK Platform | **35** | `android/variables.gradle` 里指定 |
| Build-Tools | **35.0.0** | 同上 |
| 环境变量 | `JAVA_HOME`、`ANDROID_HOME` | 改完要重开终端 |

Gradle 不用单独装，`app/android/gradle/wrapper` 自带。
下载：JDK 17 <https://adoptium.net/temurin/releases/?version=17>；
Android Studio（含 SDK Manager）<https://developer.android.com/studio>

### 1.3 部署服务端

| 工具 | 版本 |
|---|---|
| PHP | 7.2 ~ 8.0，需 `pdo_mysql`、`openssl`、`json`，建议 `mbstring` |
| MySQL | 5.5+ |
| Web | Nginx 或 Apache（配置都随包给了） |
| 面板 | 宝塔面板最省事（约 5 分钟装完） |

## 二、App 端：本地开发

```bash
cd app
cp .env.example .env.local          # Windows: copy .env.example .env.local
npm install
npm run dev                         # http://localhost:5173
```

`.env.local` 里的 `VITE_DEV_PROXY_TARGET` 指向你的后端（本机后端就写
`http://127.0.0.1:3030`）。改完 `.env.local` 必须重启 dev server。

常用命令：

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器，`/api` 自动代理到后端（不触发 CORS 预检） |
| `npm run typecheck` | `tsc --noEmit`，改完代码先跑这个 |
| `npm test` | vitest 单测（`tests/`） |
| `npm run build` | 类型检查 + 产出 `app/dist/` |
| `npm run check-env` | 打 APK 前的环境自检 |
| `npm run cap:sync` | 构建并同步到 `android/` |

## 三、App 端：出安装包

### 3.1 Debug 包（自己测试用）

```bat
cd app
scripts\build-android.bat
```

或用 PowerShell 版本：`.\scripts\build-android.ps1`。
产物在 `app/android/app/build/outputs/apk/debug/app-debug.apk`。

### 3.2 Release 包（对外发布，可覆盖升级）

**第一步：配签名**（只需做一次）

把下面四行写进**仓库外**的全局文件
（Windows：`C:\Users\<你>\.gradle\gradle.properties`；macOS/Linux：`~/.gradle/gradle.properties`）：

```properties
NAWU_STORE_FILE=C:/绝对路径/nawu-flyme/keystore/nawu-release.p12
NAWU_STORE_PASSWORD=（口令见仓库外密钥管理）
NAWU_KEY_ALIAS=nawu
NAWU_KEY_PASSWORD=（口令见仓库外密钥管理）
```

> 用工程自带的密钥库（`keystore/nawu-release.p12`）才能让**老用户直接覆盖安装**。
> 详情与安全须知见 `keystore/README.md`。

**第二步：打包**

```bash
cd app
npm run build
npx cap sync android
cd android
./gradlew assembleRelease          # Windows: gradlew.bat assembleRelease
```

产物：`app/android/app/build/outputs/apk/release/app-release.apk`
建议改名成 `nawu-v1.1.apk`（和发布渠道的 `manifest.json` 对齐）。

> 没配签名就执行 `assembleRelease` 会**直接报错**并打印配置指引 —— 这是刻意设计，
> 避免用一个默认口令签出没法升级的包。

> 升级 Capacitor 或重建原生工程（`npx cap add android`）后，务必复查
> `app/docs/BUILD.md` §4 列出的 5 处人工改动，**尤其是明文 HTTP 那两处**，
> 否则真机会连不上你自己的服务器。

## 四、服务端：部署与安装

1. **建站**：宝塔 → 网站 → 添加站点（PHP 选 7.4+，**不要**在这里建数据库）。
2. **上传**：把 `server/` 目录里的**全部内容**（含隐藏文件 `.htaccess`）上传到站点根。
   最终应为 `站点根/index.php`、`站点根/install.php`、`站点根/app/`……
3. **伪静态（漏了必定登不上）**：站点 → 设置 → 伪静态，贴入 `server/nginx.conf` 末尾那段；
   贴完点「重载配置」。Apache 用户跳过（`.htaccess` 已带）。
   不加这条的后果：首页正常、登录页正常，但登录必报「接口不存在」/404。
4. **跑安装向导**：浏览器打开 `http://你的域名/install.php`，按 5 步走：
   环境自检 → 填数据库信息（自动建库建表，表前缀 `flyme_`）→ 设管理员账号 →
   站点信息 → 完成并自动锁定。
5. **验收**：
   - `http://你的域名/` 网页版正常；
   - `http://你的域名/api/health` 返回 `ok:true`；
   - `http://你的域名/#/admin` 能登录管理后台。

**重装**：删掉 `server/storage/config.php`，再访问 `install.php`。

**目录权限**：`storage/` 需要 PHP 进程可写（宝塔默认 `www` 用户）。
建议在站点设置里勾选「防跨站攻击（open_basedir）」。

> 生产环境强烈建议上 HTTPS：App 允许明文是为了内网自建场景，
> 公网域名用 HTTPS 更安全，也让用户可以少填 `http://`。

## 五、前端改动如何同步到网页版

改完 `app/src` 后：

```bash
cd app && npm run build              # 产出 app/dist/
cd ..
node tools/sync-web-to-server.mjs    # 同步到 server/
```

脚本会做四件事：

1. 解析 `app/dist/index.html`，取出本次构建的入口 JS / CSS / preload 列表；
2. 把 `app/dist/assets/*` 拷进 `server/assets/`（同名内容一致则跳过）；
3. 同步 `brand-icons/`、`tess/`、`tessdata/`、`logo.svg`；
4. 重写 `server/app/spa-m.html` 的入口标签（相对路径 → 绝对路径）。

它**不会自动删除** `server/assets/` 里的历史 chunk，只会提示有哪些已不再被引用 ——
因为正在浏览旧页面的用户还会去动态加载它们，立刻删会导致白屏。确认无人在线后再手动清理。

只体检不写入：`node tools/sync-web-to-server.mjs --check`

**同步完上传什么？** 最省事是整个 `server/` 重传；
想快只传变化的部分：`assets/` 新文件 + `app/spa-m.html`。

## 六、版本号升级 checklist（发版必做）

版本号分散在 5 个地方，漏一处就会出现「App 显示 v1.0.34、网页版还是 v1.0.33」这种分叉。

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `app/src/lib/appVersion.ts` | `APP_VERSION = '1.1'` |
| 2 | `app/android/app/build.gradle` | `versionCode`（+1）、`versionName` |
| 3 | `app/package.json` | `"version"` |
| 4 | `app/package-lock.json` | 顶层 `"version"`（用 `npm version 1.1 --no-git-tag-version` 一次改 3、4） |
| 5 | `server/storage/app-release/manifest.json` | `version` / `notes` / `file` / `fileSize` / `publishedAt` |

**注意**：`APP_VERSION` 同时被网页版引用（「我的」页、启动页会显示
「纳物 · App/网页版 v1.1」）。改它会改变构建产物的 chunk 哈希，
所以**必须重新 `npm run build` 并同步到 `server/`**。

推荐顺序：

```bash
# 1) 改版本号
cd app
npm version 1.1 --no-git-tag-version     # 同步 package.json + lock
# 手工改 appVersion.ts 与 android/app/build.gradle

# 2) 构建 + 同步
npm run build
cd .. && node tools/sync-web-to-server.mjs

# 3) 出包
cd app/android && ./gradlew assembleRelease

# 4) 发布（把 APK 放到服务端，启用 App 内检查更新）
#    把 nawu-v1.1.apk 传进 server/storage/app-release/
#    再改同目录 manifest.json（先传包、后改 manifest，顺序不能反）
#    验证：curl http://你的域名/api/app/version
```

## 七、发布与分发

### 7.1 用服务端自带的更新通道（推荐给终端用户）

把 APK 传进 `server/storage/app-release/`，改 `manifest.json`，
用户的 App「设置 → 检查更新」就能收到升级提示。
`/storage/` 直链被封，下载只能走受控的 `/api/app/download`。

### 7.2 用 GitHub Actions 自动构建（适合想省事的团队）

`app/.github/workflows/build-apk.yml` 已经写好：推 `v*` 标签或手动触发，
CI 自动构建并发布 Release。

要跑通需要先在仓库 **Settings → Secrets and variables → Actions** 里加 4 个 Secret：

| Secret | 值 |
|---|---|
| `NAWU_STORE_FILE` | `nawu-release.p12` |
| `NAWU_STORE_PASSWORD` | `（口令见仓库外密钥管理）` |
| `NAWU_KEY_ALIAS` | `nawu` |
| `NAWU_KEY_PASSWORD` | `（口令见仓库外密钥管理）` |

另外 **`NAWU_KEYSTORE_BASE64` 强烈建议一起加** ——
因为本工程包里没有把 `.p12` 提交进 `app/android/app/`（`.gitignore` 已忽略密钥库），
CI 就没有可用的密钥库文件。生成 base64：

```bash
# macOS / Linux
base64 -w0 keystore/nawu-release.p12 > keystore.b64
```

```powershell
# Windows PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("keystore\nawu-release.p12")) | Set-Content keystore.b64 -NoNewline
```

把 `keystore.b64` 的**全部内容**（一行，很长）粘进 Secret 值即可。

> 两个已知坑（都已在本工程的 workflow 里修好，换新仓库时注意别改回去）：
> ① `secrets` 上下文**不能出现在 `if:` 表达式**里，否则整个 workflow 会被判为无效，
> 表现为一次 0 job、秒级失败；② 必须声明 `permissions: contents: write`，
> 否则创建 Release 会 403。

## 八、日常迭代约定

1. **依赖方向只能向下**：`pages → store → domain/api → net → storage/lib`。
   `pages/**`、`components/**` 禁止裸 `fetch`、禁止直接 import `CapacitorHttp`/`Preferences`。
2. **网络出口唯一**：所有请求走 `app/src/net/httpClient.ts`；
   POST 体一律 JSON（服务端只读 `php://input`，表单会被静默忽略）。
3. **不动本地键名与 ID 算法**：`guifou.<collection>`、`guifou.kv.*`、
   `newId()` 实现、快照里的 `app: "guifou-web"` —— 改了就与老备份不互通。
4. **服务端表前缀 `flyme_` 不要改**（改了老库对不上，除非写迁移脚本）。
5. **改完前端必跑**：`npm run typecheck` + `npm test` + `npm run build` +
   `node tools/sync-web-to-server.mjs`。
6. **改了服务端 PHP**：直接把改动文件传上去即可，纯 PHP 无需构建；
   `server/assets/` 只在改了前端时才需要更新。

## 九、疑难速查

| 现象 | 原因 / 处理 |
|---|---|
| 真机「无法连接到服务器」但地址没错 | 明文 HTTP 被拦：检查 `AndroidManifest.xml` 的 `usesCleartextTraffic` 与 `network_security_config.xml`（`app/docs/BUILD.md` §4） |
| 网页版改了前端不生效 | 忘了同步：`node tools/sync-web-to-server.mjs`；再确认浏览器强刷（`assets/` 文件名带哈希，一般不需要） |
| 网页能打开，但登录/注册提示「接口不存在」或 404 | **伪静态没生效**（最常见）：`/api/*` 没转发给 `index.php`。站点 → 设置 → 伪静态 贴 `try_files $uri $uri/ /index.php?$query_string;` 后重载 Nginx。自查：`/api/health` 应返回 `{"ok":true,"db":true}` |
| 网页版白屏 / 404 | 同上，也是伪静态没生效 |
| 登录报「请输入正确的邮箱地址」 | POST 体不是 JSON —— 必须走 `net/httpClient.ts`，禁止 form-urlencoded |
| `assembleRelease` 报「缺少 APK 签名配置」 | 按 `app/docs/BUILD.md` §6.1 配好四个 `NAWU_*` 键 |
| `SDK location not found` | 设 `ANDROID_HOME`，或写 `app/android/local.properties` 的 `sdk.dir=` |
| Gradle 下载卡死 | 在 `app/android/settings.gradle` 的 `repositories` 里把阿里云镜像放到 `google()` 之前 |
| App 提示有新版本但下载失败 | 先确认 `storage/app-release/` 里的 APK 文件名与 `manifest.json` 的 `file` 一致、`fileSize` 与真实字节数一致 |
| 安装向导第 2 步连不上数据库 | MySQL 地址本机写 `127.0.0.1`；库不存在时向导会尝试自建，权限不足就先在面板手动建库 |
| 品牌图标空白 | 确认站点根有 `brand-icons/`（177 个文件），且 `storage/brand-icons/` 可写 |
| 邮件/验证码发不出 | 管理后台 → SMTP 设置里配置发信邮箱 |

## 附：一份可复制的「改完前端 → 上线」脚本

`app/package.json` 里已有 `build` / `cap:sync` 等命令，同步脚本建议这样串：

```bash
cd app && npm run typecheck && npm run build && cd .. && node tools/sync-web-to-server.mjs
```

跑完无报错，就可以把 `server/` 的增量文件传上去收工了。
