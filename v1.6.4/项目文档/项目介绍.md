## 一、这是什么

**纳物**是一款「记录你买了什么、值不值、还剩多少价值」的本地优先记账 App。

核心不是流水账，而是**物品的生命周期账**：一件东西买来多少钱、摊到每天多少钱、
用了几次、最后卖了多少、净赚还是净亏 —— 用「日均成本」替代「花了多少钱」的心理账户。

三种形态，**同一份 React 源码**产出：

| 形态 | 产物 | 承载方式 |
|---|---|---|
| Android App | `nawu-v1.6.4.apk` | Capacitor 7 原生壳加载 `app/dist` |
| 手机网页版 | 站点首页 `/` | Nginx + PHP 托管 `server/` |
| PC 网页版 | 同上（≥1024px 自动切桌面壳） | 同上 |

**数据 100% 存在用户设备本地**（Capacitor Preferences / localStorage），
服务端只承担「账号 / 云备份 / 品牌图标 / 天气 IP 归属地 / 更新分发」，
**不持有用户业务数据** —— 这是产品级红线，不要为了省事把账本塞进 MySQL。

## 二、核心功能

### 1. 物品库（主线）
- 入库：名称、价格、日期、分类、图标/图片、备注、附加费用（运费/配件/维修）
- 成本核算：**总投入 = 买入价 + 附加费用**；**日均成本 = (总投入 − 转卖价) ÷ 持有天数**
- 使用计数：`使用次数` / `累计次数` → 单次使用成本
- 退役（已售出）：填出售价 → 自动算**净赚 = 出售价 − 总投入**，正收益自动记入生活流收入
- 目标日均：低于目标即 100% 达成，超过按 `目标/实际` 线性衰减

### 2. 对话记一笔（本轮重点迭代）
一句话说清，自动识别成卡片，确认即入库：
- **二手买卖一体**（v1.3.6 新增）：`买入N95笔记本360元，卖出560元，手续费千分之6、快递费20、杂费10`
  → 一张卡跑完「入库（带买入价）+ 卖出信息（售价/费率/快递/杂费）→ 自动标记已售出 → 净赚进生活流」
- **已提交条目可复制、可就地编辑重发**（v1.3.6 新增）：错一个字/一个数字不用整段重打
- **语音输入走端侧识别**（v1.3.6 改造）：Android 12+ 用系统离线识别器，服务端停机也能用
- 识图记账：订单/小票截图 → 本地 Tesseract OCR（`chi_sim`）或 AI 视觉
- 查询意图：「昨天买了什么 / 这周最贵的是什么」直接答，不弹卡
- 纠正即学习：改了大类/小类 → 沉淀规则，同步云端账号，换设备继续命中

### 3. 生活流 / 订阅 / 报表 / 冷静池
- 生活流：一笔笔消费，带「归 / 需 / 否」判断（这笔花得值不值）
- 订阅：周期扣款、下次续费提醒、账单四态（待扣/已扣/跳过/失败）、退款
- 报表：月度结构、分类占比、日均成本榜
- 冷静池 / 心愿单：想买先放进去，过了冷静期再决定

### 4. 备份与多服务器
- 本地快照自动备份（按变更条数节流）+ `.flyme` 加密备份文件导出/导入
- 云备份：整体快照上传自建服务器
- 一台设备最多配 3 台服务端，登录态按服务器分槽（`flyme.sessions`），切换免重登

### 5. 在线更新（双通道）
- **App 端**：更新渠道 `app-manifest.json` → 增量补丁（NAWU-PATCH1）优先，
  失败自动降级重下全量包；再不行回退用户自己连接的服务器 `/api/app/version`
- **服务端**：管理后台「在线更新」拉 `manifest.json` → 分片下载 → sha256 校验 →
  备份 → 解包 → 原子替换 → 健康自检（失败自动回滚）
- **★v1.6.4 渠道变更**：渠道 = **当前正在运行的服务端站点根目录** `https://x.133388.xyz/`
  （旧公共分发目录 `106.53.204.29/nawu-update/` 已下线）。发布只需把
  `app-manifest.json` + `nawu-vX.Y.Z.apk`（+ 可选增量包 / 服务端包）丢进站点根目录，
  用 `tools/publish-ota.py` 生成清单、`tools/verify-update-channel.py` 体检

## 三、技术栈

### 前端（`工程/app`）
| 层 | 选型 |
|---|---|
| 框架 | React 18.3 + TypeScript 5.9 |
| 构建 | Vite 5.4（`base: './'`，Capacitor 需要相对路径） |
| 样式 | Tailwind CSS 3.4（**桌面端只能用 `dt:` / `dtxl:` 变体，禁用裸 `lg:`**） |
| 状态 | Zustand 5（六个 store） |
| 路由 | react-router-dom 6（HashRouter，`/#/admin` 进后台） |
| 原生壳 | Capacitor 7.6（Android SDK 35 / JDK 17） |
| OCR | tesseract.js 5.1 + 包内 `chi_sim.traineddata` |
| 测试 | Vitest 2.1 + jsdom（44 文件 / 418 例） |

### 服务端（`工程/server`）
| 项 | 说明 |
|---|---|
| 语言 | PHP 7.2 ~ 8.0，**零第三方依赖**（不需要 Composer） |
| 数据库 | MySQL 5.5+（生产用 5.6），表前缀 `flyme_`，安装向导自动建表 |
| Web | Nginx（或 Apache，`.htaccess` 已带） |
| 目录 | `index.php` 统一入口，`app/Api.php` 路由，`app/lib/*` 分层 |
| 依赖扩展 | `pdo_mysql`、`openssl`、`json`、`mbstring`（建议）、`zip`（在线更新必需） |

### 部署拓扑（生产）
```
                    ┌──────────────────────────────┐
   手机 App ────────►│ 80 端口：纳物记账后端          │
   网页版   ────────►│  Nginx + PHP + MySQL 5.6      │
                    │  站点根 = server/ 内容         │
                    └──────────────────────────────┘
                                  ▲
                                  │ /api/admin/server/* 拉清单
                    ┌──────────────────────────────┐
   App 检查更新 ────►│ 站点根目录 https://x.133388.xyz │
                    │  app-manifest.json（App）      │
                    │  manifest.json（服务端自更新）  │
                    │  *.apk / *.patch / *.zip       │
                    └──────────────────────────────┘
```

- 主服务端：**80**，公网开放，`/api/health` 应返回 `{"ok":true,"db":true}`
- 更新通道：**站点根目录**（同一 443 站点），`/app-manifest.json` 应返回合法 JSON
- 更新源地址在 `app/src/lib/appVersion.ts` 的 `OFFICIAL_UPDATE_CHANNEL`
  （**全工程唯一硬编码的官方地址**，换服务器只改这一处）

## 四、代码仓库与分发

| 仓库 | 内容 | 说明 |
|---|---|---|
| `github.com/lingli00/nawu-flyme` | 纯净开源工程，按 `vX.Y.Z/` 目录归档 | 剔除个人隐私/私有配置，仅保留通用更新通道 |
| `github.com/lingli00/nawu` | **App 端源码（根目录即工程）**，Release 挂 APK | 云端打包工作流在这里，给终端用户下载 APK |

> ⚠️ 两个仓库的分工容易记反：`nawu` 不是「只放安装包」，它的**根目录就是 APP 源码**，
> 根级 `.github/workflows/build-apk.yml` 是唯一能跑通的云端打包入口。
> `nawu-flyme` 里的 `vX.Y.Z/app/.github/workflows/` **从来没生效过**（GitHub 只认仓库根目录）。

**发版三件套**：增量差分包（`.patch`）+ 全量 APK + 完整工程 zip。
Release 说明必须按「新增 / 修复 / 调整 / 优化」四段写，与历史风格一致。

## 五、本地开发三条命令

```bash
cd 工程/app
npm install                 # 首次
npm run dev                 # http://localhost:5173
npm run typecheck && npm test    # 质量门：tsc 零错 + 418 例全绿
npm run build               # 产出 app/dist
cd .. && node tools/sync-web-to-server.mjs   # 前端产物 → server/
```

**改完前端一定要跑最后那条同步**，否则网页版还是旧界面（这是本项目最高频的坑之一）。
