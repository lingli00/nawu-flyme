## 五、后续发版怎么做

### 方式 A：面板（推荐，浏览器操作）

1. 打开 `http://106.53.204.29:2233/nawu-update/nawu-update-panel.php`，口令 `NaWu@2233Panel`
2. 上传 `nawu-vX.Y.Z.apk` 全量包
3. 上传 `旧版本-to-X.Y.Z.patch` 增量包（有几个旧版本就传几个）
4. （可选）上传 `nawu-server-vX.Y.Z.zip` 供服务端在线更新
5. 点「重建清单」——`app-manifest.json` 与 `manifest.json` 自动重算 sha256 / size

### 方式 B：命令行（与本次部署同源）

```bash
# 1. 生成增量包（工程自带工具，内部自校验）
python 工程/tools/make-app-patch.py 旧包.apk 新包.apk 旧版本-to-新版本.patch

# 2. 组装通道目录
python deploy/build-channel.py out 新包.apk 补丁目录 deploy/notes-X.Y.Z.txt

# 3. 上传 APK / 补丁 / app-manifest.json 到站点通道目录
#    （面板 API：/files/upload，字段 blob + file_name + path + start + total + size）
```

> ⚠️ 顺序：**先传包，后改清单**。反了会在中间窗口期让客户端拿到 404。

### 服务端更新

80 站点的服务端更新走「上传整包 → 解压覆盖 → 保留 `storage/config.php` 与 `storage/app-release/`」。
本次已固化伪静态与发布清单，覆盖时**不要动** `storage/` 目录。
