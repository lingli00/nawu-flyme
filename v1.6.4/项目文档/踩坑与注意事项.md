> 目的：把「已经付过学费的坑」写死在这里，避免下一个 AI/下一个人再踩一遍。  
> 最后更新：2026-11-01 · v1.6.4（新增铁律 6：输入框光标；更新渠道改指站点根目录）

## 一、铁律（违反必炸）

### 1. 中文输入法（IME）铁律 —— 本项目最高频事故源

Android WebView 在中文输入法**组合期**经常不派发 `change` 事件。  
所以：**凡是要过输入法的字段（名称、备注、费用说明…），提交时必须读 DOM 真值，不能读 state。**

```tsx
// ❌ 错：输入法组合期 state 还是旧的
<input value={name} onChange={(e) => setName(e.target.value)} />
// ✅ 对：非受控 + 提交时读 ref
<input ref={nameRef} defaultValue={name} />
const name = nameRef.current?.value ?? '';
```

**已经踩过的四个受害者**：

1. 物品名称 → v1.1.10 修复
2. 物品备注 → v1.1.10 修复
3. 对话记一笔卡片字段 → v1.2.0 起全非受控
4. **附加费用「说明」→ v1.3.6 修复**（就是本次的「名称丢失」恶性 Bug：  
   金额是纯数字不走 IME 所以存住了，名称被 IME 吞了 → 只剩金额）

> 反推价值很高：看到「某个字段偶尔是空的 / 数字在、文字没了」，先怀疑 IME 漏发 onChange。

### 2. 前端改完必须同步到服务端

```bash
cd app && npm run build && cd .. && node tools/sync-web-to-server.mjs
```

只打 APK 不同步 → 网页版还是旧界面、版本号对不上。  
反向也成立：`server/assets/` 是构建产物，**不要手改**。

### 3. 依赖方向只能向下

`pages → store → domain/api → net → storage/lib`  
`pages/**`、`components/**` 禁止裸 `fetch`，禁止直接 import `CapacitorHttp` / `Preferences`。  
所有请求走 `src/net/httpClient.ts`，POST 体一律 **JSON**（后端只读 `php://input`，  
表单会被静默忽略 → 报「请输入正确的邮箱地址」这种莫名其妙的话）。

### 4. 桌面端布局只能用 `dt:` / `dtxl:` / `dt2xl:`，禁用裸 `lg:`

裸 `lg:` 会在手机横屏/分屏时串味（手机壳 + 桌面布局）。

### 5. 存储协议不许改名

`guifou.<collection>`、`guifou.kv.*`、`newId()`、快照里的 `app:'guifou-web'` —  
改了老用户的备份就全废。产品改名 ≠ 存储层改名。

### 6. ★ 输入框光标铁律（v1.6.4）——「删一个字光标就飞到尾」

**症状**：光标点到文字中间，删一个字或打一个字，光标立刻跳到整句末尾，
后面打的全落在句尾；改一个数字等于重打一遍。中文输入法下尤其明显。

**两层成因，只修一层必复发**：

| 层 | 成因 | 正确做法 |
|---|---|---|
| 原生 | `capacitor.config.ts` 里 `captureInput: true`。Capacitor 的 `CapacitorWebView.onCreateInputConnection()` 一旦读到它，就返回自己 new 的 `BaseInputConnection`，顶掉 Chromium 的 `WebViewInputConnection`。前者是给硬键盘用的简化实现，**不管输入法组合区**：`deleteSurroundingText`（删一个字）退化成「整段重设文本」、`commitText` 也把 selection 顶到末尾 | 保持 **`captureInput: false`**（Capacitor 默认值）。本项目没有任何硬键盘捕获需求 |
| JS | 输入事件里改 DOM（`style.height = scrollHeight` 自适应、过滤后回写 `value`）→ WebView 重排选区 | 一律走 `src/lib/caretGuard.ts`：**先读 selectionStart/End → 再动 DOM → 立刻恢复 → `requestAnimationFrame` 下一帧再确认一次** |

**三条禁令**：

1. 禁止在输入框里手写裸的 `el.style.height = ...`（用 `autoGrowTextarea`）；
2. 禁止给输入框加 `key`、禁止用条件渲染把它换掉、禁止改成受控 `value` ——
   DOM 一重建，光标必丢；
3. 禁止删掉 `requestAnimationFrame` 那一帧的二次恢复。选区重排发生在事件之后的
   下一帧，只做同步恢复会被覆盖。

> 已配护栏：`tests/caret-guard.test.ts` 直接读源码断言上面三条，
> 谁把 `captureInput` 改回 `true` 或删掉 rAF，测试立刻红。
>
> 另一个反直觉点：**读布局也可能把光标挪走**。`autoGrowTextarea` 里读完
> `scrollHeight` 之后再去现场读一次 selection，拿到的可能已经是「末尾」——
> 所以必须把**函数入口处**记下的光标传进 `preserveCaret()`，不能让它现场再读。

## 二、对话记一笔 / 语音（v1.3.6 重点）

### 1. 「卖出」这个词原本不在卖出规则里

`RE_SELL` 只有 `卖了|卖掉|出掉|出售|回血|转让|闲鱼出了|已出|退役`，  
**没有「卖出」**，于是「卖出560元」被当成一笔 560 的支出记进生活流。  
v1.3.6 的 `ai/trade.ts` 自带 `SELL_RE`（含「卖出/出手/转手」），并且**必须先于分句拦截**。

### 2. 买卖一体的识别一定要在「分句之前」

一条消息被逗号切开就变成两张互不相认的卡：物品卡还没落库，卖出卡去找物品 →  
报「没找到与「xxx」匹配的物品，请先入库」。  
所以 `SmartRecordDock.doSend()` 里 `detectTrade()` 要放在 `splitTasks()` 之前。

### 3. 手续费不新建字段

手续费/快递费/杂费一律折进物品的 `extraFees`，  
`sellProfit = 售价 − (买入价 + extraFees)` 的既有口径不动，  
净赚 / 日均成本 / 生活流收入自动就是对的。**别为手续费加新字段**，会分裂口径。

### 4. 语音：Web Speech 在 Android 上其实是「云端识别」

`webkitSpeechRecognition` 在 Android WebView 里把音频送到在线识别服务 ——  
服务端/外网一抖就报 network 错误，看起来像「我们服务器挂了导致语音不可用」。  
v1.3.6 改成原生 `NawuSpeech` 插件：

- Android 12+（API 31）用 `SpeechRecognizer.createOnDeviceSpeechRecognizer()` —— 纯本机；
- 低版本退回系统识别器 + `EXTRA_PREFER_OFFLINE=true`；
- 两者都没有 → 明确提示「本机没有离线语音引擎」，不再假装在听。

**必须遵守的三条**：

- `SpeechRecognizer` 只能在**主线程**创建/销毁（插件里全部投递到 `runOnUiThread`）；
- 同一时刻只留一个实例，`destroy()` 前先 `cancel()`；
- 本地插件要在 `MainActivity.onCreate()` 的 `super.onCreate()` **之前** `registerPlugin()`，  
  晚了 Bridge 已建好，前端调它只会得到「插件不存在」。

### 5. 端侧识别也有前提

系统得装了中文离线语音包（Flyme/多数国行 ROM 自带；部分精简包没有）。  
真机自测顺序：`isAvailable()` → 长按说话 → 断网再试一次 → 关掉自家服务端再试一次。  
**三种情况下都应该能出字**，否则说明还在走云端。

## 三、服务端部署（宝塔）

### 3.1 标准生产环境

- Nginx + PHP 7.2~8.0（`pdo_mysql` / `openssl` / `json` / `mbstring` / `zip`）+ **MySQL 5.6**
- 站点根 = `server/` 的**全部内容**（含隐藏文件 `.htaccess`）
- 运行目录设 `/`，勾选「防跨站攻击 open_basedir」
- `storage/` 必须 PHP 进程可写（宝塔默认 `www`）

### 3.2 伪静态（漏了必定登不上）

宝塔 → 网站 → 设置 → 伪静态，贴：

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

不加的后果：首页正常、登录页正常，**但登录必报「接口不存在」/404**。  
自查：`/api/health` 应返回 `{"ok":true,"db":true}`。

### 3.3 安装与重装

- 首次：浏览器打开 `http://域名/install.php`，5 步走（环境自检 → 数据库 → 管理员 → 站点 → 完成锁定）
- 重装：删 `server/storage/config.php` 再访问 `install.php`
- 表前缀固定 `flyme_`，**不要改**（除非写迁移脚本）

### 3.4 目录权限 / 安全

- `storage/` 可写；`.user.ini` 已被 open_basedir 覆盖，更新任务的临时文件都放  
  `storage/server-release/`，**不要往别处写**
- `storage/`、`app/` 目录禁止直接访问（`nginx.conf` / `.htaccess` 已配）
- 生产建议上 HTTPS；App 允许明文只是为了内网自建场景

## 五、在线更新机制的坑（服务端自更新）

| 现象                              | 原因 / 处置                                                                  |
| ------------------------------- | ------------------------------------------------------------------------ |
| 轮询一直「连接超时（15s）」→「已有更新任务正在进行」死循环 | 单片预算 `SLICE_MS` 曾设 18s > 前端 15s 超时。**必须显著小于前端超时**（现 5s）                  |
| manifest 拉回来却是 HTML             | 伪静态把 `/manifest.json` 拦成了 SPA 页；或更新源少了目录 `/nawu-update/`                 |
| App 检查更新永远「已是最新」                | 频道地址被 URL 归一化剥掉路径（v1.1.1 修的经典坑）；用 `channelBase()` 拆 origin + dir         |
| 更新后网页仍加载旧 chunk                 | `planDiff` 认为旧文件仍在包内；同步脚本不自动删历史 chunk（怕在线用户白屏）                           |
| 清完旧文件后白屏                        | 站在旧页面的用户还要动态加载老 chunk。**只删已无引用的，且低峰期删**                                  |
| 增量包校验失败                         | 临时文件残留 / 大小不符 / sha256 不符 → v1.3.3 起自动降级重下全量包（`usedFallback` 只降一次）       |
| 服务端更新后 500                      | 看 `storage/server-release/jobs/<id>.json` 与 `history.json`；健康自检连续失败会自动回滚 |
| `qqwry.dat` 缺失                  | GitHub 包因体积限制未带；区县定位降级为只显示省市，放置方法见 `server/app/data/README.md`           |
| 服务端「连不上更新源」               | 旧默认源 `106.53.204.29/nawu-update/` 已下线（v1.6.4 实测 502/拒绝）。默认源已改指站点根 `https://your.domain.com/`，后台可覆盖 |
| 渠道改了但 App 还说「已是最新」         | ①`app-manifest.json` 没传到站点根；②清单里 `version` 不比本机大；③`apk.url` 写成了绝对地址且协议/域名不对 |
| 发布更新三步                      | `python tools/publish-ota.py --dir dist-ota` 生成清单 → `--upload` 推到站点根 → `python tools/verify-update-channel.py` 体检 |

## 七、本轮新增注意事项（v1.3.6 特有）

> v1.3.6 已实际出包并发布，本节记录**过程中踩到的真坑**，下次发版直接照做。

### 1. ★ GitHub Actions 只认仓库**根目录**的 `.github/workflows/`

`nawu-flyme` 里每个版本目录都带 `vX.Y.Z/app/.github/workflows/build-apk.yml`，
**这在 GitHub 上从来没生效过** —— 工作流只在仓库根 `.github/workflows/` 下才会被注册。
查询 `GET /repos/{o}/{r}/actions/workflows` 返回 `total_count: 0` 就是铁证。

- 能云端打包的是 **`nawu`**（根目录就是 APP 源码，根级 `build-apk.yml` 正常）。
- 云端出包：`POST /repos/{o}/{r}/actions/workflows/{id}/dispatches {"ref":"main"}`，
  需要 PAT 有 **Actions: write**。
- 校验权限的小技巧：拿不存在的 ref 试触发，返回 **422「No ref found」= 有权限**，403 = 没权限。
- 注意：用 API 建 tag **不会**触发 `on: push: tags`（没有 push 事件），必须用 dispatch。

### 2. ★ `nawu` 是私有版，**不能用 flyme 的脱敏文件覆盖**

| 仓库 | 性质 | 特征 |
|---|---|---|
| `nawu` | 私有完整版 | 更新通道 `106.53.204.29:2233`、内网 `10.0.0.209:2222 / :3030` |
| `nawu-flyme` | 纯净开源版 | 通道 `127.0.0.1:2233`、内网 `192.168.1.100` |

直接整目录同步会把真实地址冲成占位地址。正确做法（本次用的）：

1. 取 `v1.3.5/app` 对应文件作**基线**，与 `v1.3.6/app` 比对：
   - 相同 → 该文件的差异纯属脱敏，**不要动私有版**；
   - 不同 → 才是真实改动，才写入。
2. 本次 30 个差异文件里只有 **9 个**是真实改动，其余 21 个是脱敏噪声。
3. 推完必须复核关键行还在：`OFFICIAL_UPDATE_CHANNEL` 是否仍是 `106.53.204.29:2233`。

### 3. ★ 换行符：本地 CRLF vs 仓库 LF

本机编辑会产出 CRLF（本次 26 个文件），仓库统一 LF。
不转换直接推，GitHub 上会显示「整个文件都改了」，diff 全废。
**推送前统一 `\r\n → \n`**（`.png/.jar/.p12` 等二进制别碰）。

### 4. 本机 `github.com:443` 被代理阻断，git 用不了

实测：`github.com` → `000`（阻断）；`api.github.com` / `codeload.github.com` / `uploads.github.com` / `objects.githubusercontent.com` → 正常。
所以 `git clone / git push` 全失败（`CONNECT tunnel failed, 502`）。可行替代：

| 目的 | 办法 |
|---|---|
| 取仓库内容 | `https://codeload.github.com/{o}/{r}/tar.gz/refs/heads/main`（注意：代理会**截断**大包，必须 `gzip -t` 验完整性） |
| 取单个文件 | `api.github.com/repos/{o}/{r}/contents/{path}` + `Accept: application/vnd.github.raw` |
| 提交代码 | **Git Data API**：blobs → trees(`base_tree`) → commits → PATCH refs/heads/main |
| 上传 Release 资产 | `POST https://uploads.github.com/repos/{o}/{r}/releases/{id}/assets?name=...`（**必须用 curl**，Python urllib 会报 `CERTIFICATE_VERIFY_FAILED`，代理做了 TLS 拦截） |
| 下载 Release 资产 | `GET api.github.com/repos/{o}/{r}/releases/assets/{id}` + `Accept: application/octet-stream` |
| 下载构建产物 | `GET api.github.com/repos/{o}/{r}/actions/artifacts/{id}/zip`（需 Actions:read） |

Git Data API 的两个坑：
- 新文件路径必须相对**仓库根**，用 `os.path.relpath(path, WORK)`，写错会得到 `../xxx` → `422 tree.path contains a malformed path component`。
- 906 个 blob 逐个上传时，代理偶发 `400 malformed` / `401 Unauthorized` / `408 inactivity`，**必须带重试 + 断点续传缓存**（本次缓存条数 = 已成功 blob）。

### 5. ★ NAWU-PATCH1 增量包的生成

仓库里**没有**生成脚本（注释指向的 `.gh/make-app-patch.py` 并未收录），格式只能从
`android/app/src/main/java/com/guifou/app/NawuPatch.java` 反推：

```
magic "NAWUPATCH1"(10) | newSize(int64) | ctrlLen/diffLen/extraLen(int32 x3)
ctrl  = raw deflate( int64 x, y, z 三元组序列 )
diff  = raw deflate( y 字节叠加量，new = (old + diff) & 0xFF )
extra = raw deflate( z 字节字面量 )
```

语义：`oldPos += x; 复制 y 字节 old + diff; oldPos += y; 追加 z 字节 extra`。

因为两端都是 ZIP，**按条目对齐**最省事：未改动条目整段 `copy`（diff 全 0），改动条目走 `extra`。
本次结果：11.73MB → 补丁 **3.23MB（27.5%）**。
**生成后必须回放校验**：用旧 APK + 补丁合成一遍，sha256 要等于新 APK 才发。

### 6. 出包与发布的实际顺序（照抄即可）

1. 推代码到 `nawu` main（17 个文件）；
2. `dispatch` 工作流 → 等 `Build APK` 成功（约 6 分钟）；
3. 下载 artifact → `nawu-v1.3.6.apk`；
4. 下载上一版 APK → 生成补丁 → 回放校验；
5. 建 tag + Release（正文取本项目的四段式：新增 / 修复 / 删除调整 / UI 优化）→ 传 APK + 补丁；
6. `nawu-flyme` 推 `v1.3.6/` + 根 README → Release 传工程 zip / 服务端 zip / 面板 php；

## 九、纯净包与换机器复原（v1.6.2 备份）

> 目的：说清楚「备份包里有什么、没什么、为什么」，以及换一台机器怎么 30 分钟内接着开发。  
> 对应交付物：`纳物NaWu-纯净包-v1.6.2-<日期>.tar.gz`

### 1. `node_modules` 和 `dist` 是「可再生的派生产物」，不是必要工具

| 目录 | 是什么 | 能否再生 | 是否进备份包 |
| --- | --- | --- | --- |
| `node_modules/` | `npm install` 装下的第三方依赖目录（**不是工具本身**，是产物） | ✅ 能，靠 `package.json` + `package-lock.json` + 联网从 npm 重装 | ❌ 不进（体积大、含平台原生模块） |
| `dist/` | `npm run build` 打出来的生产包（纯构建产物） | ✅ 能，靠源码重新构建 | ❌ 不进（开发用不到，部署时现打） |

真正「必要的运行环境」是装在目标机上的：**Node.js + npm**（前端/App）、**Android Studio + JDK 17 + SDK 35 + Gradle**（出安卓包）、**PHP 7.2+**（服务端）。这些没法塞进 tar.gz，必须在新机器单独装。

### 2. 备份包里到底有什么

- `工程/`：完整源码 **912 个文件**（已排除 `node_modules` / `dist`），含 `package-lock.json`（关键：保证依赖精确还原）；
- `发布-最新/`：`nawu-server-v1.6.2.zip` + `nawu-v1.6.2.apk`（当前最新服务端 / App 纯净包）；
- `项目文档/`：项目介绍 / 项目结构说明 / 变更日志 / 踩坑与注意事项 / 部署记录-服务器；
- 注意：`app/public` 与 `server` 下的 vosk / tesseract / `chi_sim` 中文模型是**源码自带的运行素材**（App 语音+OCR 必需），已随工程打入，不是 `node_modules`/`dist`。

### 3. 换机器复原步骤（照抄）

```bash
# 1) 解压纯净包
tar -xzf 纳物NaWu-纯净包-v1.6.2-<日期>.tar.gz

# 2) 前端 / Web：还原依赖（package-lock.json 在，版本一致）→ 起开发服
cd 工程/app && npm install      # 或 npm ci（严格按 lockfile）
npm run dev                     # 本地开发；生产出包用 npm run build

# 3) App 安卓包：需 Android Studio + JDK17 + SDK35 + Gradle
npx cap sync android            # 把 web 构建同步进原生工程
# 之后用 Android Studio 打开 工程/app/android 出包

# 4) 服务端：PHP 环境，直接解压纯净包里的服务端 zip 到 web 根
#    cd 工程/server 按 server/README.md 部署；或解压 发布-最新/nawu-server-v1.6.2.zip
#    别忘了配伪静态（见第三章 3.2）和跑 install.php
```

版本号四处已统一为 `1.6.2`（`server/app/VERSION`、`app/package.json`、`android/app/build.gradle` 以及 `package.json` 的版本字段）。

### 4. 唯一极端风险（日常几乎遇不到）

若某个依赖被作者从 npm **下架 / 删版本**，`npm ci` 会装不到对应版本。那种情况才需要把 `node_modules/` 也打进备份包（代价：体积涨到 ~350MB，且原生模块可能受目标系统影响）。正常发布包前提下**不需要**。
