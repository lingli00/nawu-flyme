## v1.6.4（2026-11-01）

> 本版两条主线：**修复「输入框光标在文本中间编辑后跳到末尾」**（恶性体验 Bug，含原生层根因）、
> **更新渠道切到自己正在运行的服务端站点根目录**（旧公共分发目录已下线）。

### 1. 光标 Bug 修复（P0）

用户复现：输入一段文字 → 光标点到文字中间 → 删一个字或打一个字 → 光标立刻跳到整句末尾，
后续输入全部落在句尾，改一个数字等于重打一遍。

根因是**两层叠加**，只修一层都会复发：

| 层 | 成因 | 修复 |
|---|---|---|
| 原生 | `capacitor.config.ts` 的 `android.captureInput: true`：Capacitor 用自己 new 的 `BaseInputConnection` 顶掉 Chromium 的 `WebViewInputConnection`。前者是硬键盘用的简化实现，不管输入法组合区（composing region）——`deleteSurroundingText`（删一个字）退化成「整段重设文本」，`commitText` 也把 selection 顶到末尾 | 改回 Capacitor 默认 `false`（本项目无硬键盘捕获需求），交还原生输入连接 |
| JS | 「对话记一笔」输入框每次 `input` 都改 `style.height`（自适应高度）来撑高，Android WebView 在组合期重排选区，光标被甩到末尾 | 新增 `src/lib/caretGuard.ts`：**先读 selectionStart/End → 再动 DOM → 立刻恢复 → `requestAnimationFrame` 下一帧再确认一次**；单行输入（最高频路径）只做只读测量，**完全不动样式** |

- 输入框保持**非受控**（`defaultValue`），不允许因改值重挂载整个输入框 DOM
- `caretGuard.ts` 文件头写了「禁止删除」的护栏说明，并配 `tests/caret-guard.test.ts` 源码断言：
  后续重构删掉 `requestAnimationFrame` 二次恢复、或把 `captureInput` 改回 `true`，测试直接红

### 2. 更新渠道切到「自己正在运行的服务端站点根目录」

- 旧渠道 `http://106.53.204.29/nawu-update/` **已下线**（实测连不上），
  表现为 App「检查更新」永远显示「已是最新」、服务端「在线更新」报「连不上更新源」
- 新渠道 = `https://x.133388.xyz/`（站点根目录），发布只需把文件丢进根目录：
  - `app-manifest.json` — App 检查更新清单
  - `nawu-vX.Y.Z.apk` — 安装包本体（清单里写相对文件名）
  - `<旧版>-to-<新版>.patch` — 可选，增量包（有则优先走增量）
  - `manifest.json` + `nawu-server-vX.Y.Z.zip` — 服务端自更新通道（同一根目录）
- 为什么用 https：站点 80 端口对全部请求 301 → https（HSTS），
  APK 断点续传（Range）跟随跳转有兼容风险，渠道地址直接写 https 可少一次跳转
- 服务端 `GF_Update::DEFAULT_SOURCE` 同步改为站点根（与 App 端同一个地址），
  后台仍可覆盖为任意公网源
- 新增两个工具，发版不再依赖 2233 面板：
  - `tools/publish-ota.py` — 扫渠道目录 → 生成 `app-manifest.json` / `manifest.json`（字段口径与面板一致）→ 可 `--upload` 直传 FTP
  - `tools/verify-update-channel.py` — 按客户端判定链路逐项体检：清单可达 / 字段齐全 / 相对地址补全 / 包大小 / Range 206 / sha256 / 「有无更新」结论

## v1.5.0（2026-10-22）

> 大版本：更新渠道重构 + 2233 端口整合 + 报表口径 + 离线语音修复 + 断点续传。

### 1. 更新渠道按「当前服务器」自动选择（需求核心）

- 新规则：**当前服务器已发布更新包 → 只走该服务器通道**（全量包，`/api/app/download`）；
  服务器没有发布 / 版本不新 / 未连接 → **走官网渠道**（含增量补丁）
- App 内不提供渠道选择；切换服务器后下一次检查自动跟随
- 其他部署者在自己后台上传更新包即形成自己的通道，App 连接后即可收到
- 新增**更新来源日志**：`localStorage['nawu-update-check-log']` + 设置页展示
  （渠道 = 官网/当前服务器、远端版本、判定原因），并 console 输出便于真机排查

### 2. 2233 端口下线，面板整合到 80 端口后台

- 更新通道目录迁到 **80 端口** `http://106.53.204.29/nawu-update/`（静态，支持 Range）
- 后台「在线更新」新增**更新通道**卡片：显示最新版本、全量包大小、增量包清单、通道地址
- 移除后台「App 安装包发布」入口及其上传/清理代码（发布统一走构建流程 `deploy/publish_app.py`）
- 服务端更新源改指 80（`Update.php DEFAULT_SOURCE` + `storage/config.php`），2233 关闭后
  服务端自更新、App 检查更新与下发均不受影响

### 3. 报表：四项指标同行

- 「支出 / 收入 / 结余 / 转卖净赚」一行四个指标，**跟随页面顶部 日/周/月/年 筛选**
- 原独立的转卖模块改为「转卖明细」，只做明细展示（同样跟随筛选），不再有自己的周期选择器

### 4. 离线语音「反复没听清」修复（P0）

- 根因一：`AudioContext` 在移动端/WebView 默认 `suspended`，未 `resume()` → 一帧音频都收不到
- 根因二：`acceptWaveformFloat(Float32Array, ctx.sampleRate)` 不做重采样，把 48kHz PCM
  直接喂 16kHz 模型 → 声学特征错位，识别结果恒为空
- 修复：`resume()` + 改用 `acceptWaveform(AudioBuffer)`（由 vosk 内部重采样）

### 5. 断点续传

- 语音模型下载改为**分片断点续传**：4MB/片落 IndexedDB + 记录已收字节，
  退出/断网/重启后发 `Range` 续传；不支持 Range 时清空重下；完成校验总大小
- APK/增量包沿用原生插件 Range 续传（已有 `.part` 保留 + sha256 校验）
- 服务端全量/增量包：80 站点静态目录原生支持 Range（实测 206）

### 版本号与质量门

- `APP_VERSION` 1.4.1 → **1.5.0**；`android versionCode 70 → 71`；`server/app/VERSION` → 1.5.0
- `tsc --noEmit` 0 错；`vitest` 472 例（更新频道断言改为 80 端口）

## v1.4.0（2026-10-22）

> 本轮 = 3 项：首页/报表统计口径重构、端侧离线语音识别、更新包保留策略。

### 1. 首页统计固定展示 + 报表承载全历史

  数据源仍是生活流 `src='goods-sale'` 记录（售价 − 总投入），不新造口径

### 2. 端侧离线语音识别（模型不打包进 APK）

- **核查结论**：旧版 APP **没有**内置任何本地 ASR 模型 —— 走的是 Android 系统
  `SpeechRecognizer`（部分 ROM 实为在线识别，服务不可达就报「系统语音服务联网失败」）
- 集成 vosk（WebAssembly）作为**本机**识别引擎：
  - 引擎 `public/vosk/vosk.js` 随包分发（5.6MB）
  - 中文模型 `vosk-model-small-cn-0.22`（41.9MB）**不打进 APK**，首次使用语音时弹窗引导下载，
    托管在自有服务器 `http://106.53.204.29/asr-model.php`（带 CORS、支持 Range、带 Content-Length 进度）
  - 下载后存 IndexedDB，之后完全本地运算：断网、服务端停机都能用
  - 总量 5.6 + 41.9 = **47.5MB ≤ 50MB** 约束
- 兜底链：本地引擎 → 系统语音 → 都不可用时明确提示「改用键盘输入”（不影响记账）
- 网页端仍保持页面内长按连续录入（不跳系统键盘）；受浏览器限制，网页版本地识别需 HTTPS 安全上下文

### 3. 更新包保留策略（最近 2 个版本）

- 新增 `deploy/prune_releases.py`：客户端全量包 / 增量补丁 / 服务端整包，只保留最近 2 个版本，
  当前两份 manifest 引用的文件永不删除；默认预演，`--apply` 才执行并自动清空回收站
- 首次执行清理频道里 1.3.7 的旧包（11.7MB），之后每次发版跑一次即可

### 版本号与质量门

- `APP_VERSION` 1.3.9 → **1.4.0**；`android versionCode 68 → 69`；`server/app/VERSION` → 1.4.0

> 本轮 = 3 项功能升级 + 4 项 Bug 修复（物品管理 / 记账流程 / 基础体验）。

### 功能升级

1. **物品编辑：手续费费率自动计算（需求 2.1）**
   - 「附加费用」区固定展示**手续费行**：填费率（%）即按出售价自动折算金额，实时预演；
     不填视为无手续费；保存后费率存 `goods.feeRatePermille`，折算金额写进 `extraFees`（口径不变）
   - 其余附加费（快递费/包装费…）仍是「添加附加费」动态行，填了才存
   - 旧数据只有手续费金额时，编辑面板按售价自动反推费率，无缝衔接
2. **记一笔：预填 + 核对模式（需求 2.2）**
   - 退役转卖 / 二手买卖卡片弹出时，说话人没提到的费用自动用物品上已存的
     手续费费率、快递费、杂费预填；用户核对无误直接提交，不再重填一遍
3. **物品搜索：分词 + 同义别名 + 重合度排序（需求 2.5）**
   - 新增 `searchGoods()`：中文 2-gram 分词，名称/标签/备注一起参与匹配；

### Bug 修复

4. **输入框光标跳位（需求 2.3，高频）**
   - 根因：二手买卖卡的 5 个数字输入是「受控 + onChange 正则改写」——在内容
     中间插入字符时 React 把改写值整体写回 DOM，光标被顶到末尾
   - 修复：改非受控（DOM 保持用户输入原样，onChange 只镜像净化值供计算，
     失焦才规整 DOM）；主输入框在中文组词期不再抖动高度
5. **APP 更新时间显示 00:00（需求 2.4）**
   - 根因：更新频道 manifest 的 `publishedAt` 只写日期（`2026-10-21`），dayjs 解析成当天零点

6. **语音输入失效（需求 2.6，两端）**
   - APP 端秒弹「语音识别失败」：Android 12+ 强制走纯离线识别器 + `EXTRA_PREFER_OFFLINE`，

7. **编辑消息卡片被输入法遮挡（需求 2.7）**
   - 就地编辑期间自动收起下方确认卡片区，屏幕完全让给输入法与编辑框；
