|---|---|---|---|---|

| **G2** | **图片上传的二进制直传分支不可用** | `Api.php:1806-1830`：`Content-Type: image/*` 时从 `php://input` 读进 `$payload`，但随后**又**走 `GF_ImageStore::put($me, ...)` 的 `decodePayload`；而 `flyme_param` 系列只看 json body —— 实际二进制路径依赖 `put()` 里"字节串本身能被 sniff"的巧合，**且 `Api.php` 里对超限的 break 判断用的是 base64 字符上限**，逻辑混乱 | 明确 `put()` 接受"原始字节/裸base64/dataURL"三态，或干脆修正文档只保留 JSON 路径（v2 文档已按"只用 JSON"写） | **中** |
| **G3** | **`/api/user/images/gc` 要从"本机记录"算出 referenced** | `ImageStore::gc` 要求 `referenced` 是**完整 sha 列表**，否则误删（`ImageStore.php:755-765`）。服务端**有**全部集合的云快照，却不肯自己算 | 加 `POST /api/user/images/gc {"mode":"scan"}`：服务端自己 scan 最新快照里所有 `image.sha256` / `/api/user/images/<sha>` 引用。对 AI 尤其重要——AI 拿不到"本机全量记录"以外的东西 | **中** |
| **G4** | **AI 侧没有聚合/统计端点** | `query` 只做 filter/sort/fields/limit，无 `$sum/$avg/groupBy`；`ask` 只覆盖 valueRecords 的少数问题、且只返回自然语言+少量 data（`NawuAI.php:717-869`） | 加 `POST /api/ai/stats`：`{collection, filter, groupBy, metric:['sum','count','avg'], field:'amount'}` → `{groups:[{key,value,count}]}`，或让 `ask` 输出结构化 `data.topCategories/trend` | **中** |
| **G5** | **`knowledge`/`image` 的 `thumb` 字段只能客户端生成** | `entities.ts:63-71` `thumb` 是"≤256px 本地缩略图 dataURL"，服务端 `cloudFromString` 不产出 | 上传时服务端用 GD/Imagick 生成 thumb 一起返回，AI 写入就能带上（离线可见）；没 GD 时保持可选 | 低 |
| **G6** | **`inbox` 无分页/无按事件查** | `inbox()` 固定回最近 200 条 pending（`AiApi.php:1925-1934`）；MAX_PENDING=500 会静默淘汰老的 | `GET /api/ai/inbox?limit=&offset=&since=`；或至少在文档里告知"最多 500 条"（v2 已写在错误表 #18） | 低 |
| **G7** | **`/api/ai/schema` 未描述图片云托管** | `AiSchema.php:68-74, 101, 174, 194` 的 image 说明里**没有 `cloud:` 形态与 `/api/user/images`**（只在 `EntityNormalize` 里支持） | 把 cloud 形态与上传端点写进 schema 字段 note，并在 `/api/ai/openapi.json` 里加图片端点（现在 openapi 只有 `/api/ai/*`） | **中**（AI 读 schema 时看不到云托管存在） |
