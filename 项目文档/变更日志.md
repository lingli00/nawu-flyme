## v1.8.0（2026-11-24）· 修复 App 四项 bug + 首包拆分 81%

> 用户提交 43.8 秒录屏 + 4 张截图，指出 4 个问题：
> ① 启动载入时连续滑动出现空白、下方仍停首页、卡几秒；
> ② 首页筛选栏明明不需要上下滑却能滑；
> ③ 多个页面底部菜单栏遮挡文字（"这是之前没有的"）；
> ④ 底栏隐藏按钮很丑，要做得优雅。

### 修复① 启动空白 + 滑动卡顿

两个独立成因叠加：

**A. 首包 1,472 KB 未做代码分割** —— 4 个 Tab 页面、全站 AI 逻辑、所有子组件全在同一个入口 chunk。
**B. 一次滑动同步挂载一整页** —— `MainShell` 在首页出现后立刻构建「生活流」整棵页面树；
且 `tabPane` 是内联箭头函数，一次 `setMounted` 让**全部 4 页渲染函数重执行**（实测连续滑动后定格 10 帧）。

修法：
- `router.tsx` 全量路由级 `React.lazy` + `routeElementFor()` Map 查表（模块级常量 element）。
- `App.tsx` 的 `tabPane` 改**模块级普通函数**；`MainShell` 的 `RecordMenu`/`SmartRecordDock` 改 `React.lazy`。
- **关键发现**：`MainShell` 静态 import 这两个组件，会把**全站 AI 逻辑**（parseService/语音/图标库）拖进首包 —— 改 lazy 后入口从 1111 KB 降至 127 KB。
- 新增 `lib/categoryIconIds.ts`（纯 id 数据，零 lucide），让种子迁移不再拉 120 个图标组件（A/B 实测省 65 KB）。
- `vite.config.ts` 移除 `vendor:['dayjs','lucide-react']` 强制合并（它会把 lucide 整库塞进 preload chunk）。

**效果：首包 1,471.6 KB → 286.7 KB（↓81%），gzip 427 KB → 99.6 KB（↓77%）**

### 修复② 筛选栏区域能上下滑

`PullToRefresh` 连同「下拉刷新」指示器渲染在 `i === idx` 门控**之外**，四个 pane 各渲染一层 →
邻页容器有内容高度但无实际页面 → 可滚。修：`PullToRefresh` + `RailSectionBoundary` + `.nw-pane-gap`
整体移入门控；筛选条加 `overflow-y-hidden` + `touchAction:'pan-x'`。
**实测四个 pane 全部 `scrollHeight === clientHeight`（溢出 0）**。

### 修复③ 底栏遮挡文字

底部避让原来**写死 112px**，且只对 pager 页面生效；非 pager 页面（设置/备份/分类/规则/服务器/AI/账号）
完全没吃到 → 被压住。修：底栏高度用 `ResizeObserver` **实测**写入 CSS 变量 `--nw-nav-occ`，
由 `.nw-pane-gap`（pager 页）与新增 `.nw-page-gap`（非 pager 页）共同消费；折叠态自动缩到 10px。
**实测 `/home` `/ledger` `/report` `/me` 滚动到底后最后一行底边均 ≤ 底栏顶边**。

### 修复④ 底栏把手优雅化

删掉右侧悬浮的 28×28 小圆钮，改为**底栏上沿正中胶囊把手**（32×4，墨色 34%，圆角 999px，命中区 68×22）：
- 单击切换折叠；按住下甩 >18px 收起、折叠态上甩 >18px 展开；拖拽中底栏 1:1 跟手。
- 悬停/按住时胶囊 32→40 并转 accent 绿（唯一的可交互暗示）。
- 折叠后底栏整体滑到屏幕下沿，只露把手 + 一枚 accent 微点；**不再用 opacity 做半透明幽灵栏**。
- 把手是 `<nav>` 的**兄弟节点**（`.nw-tabbar-wrap` 包裹），底栏内仍严格只有四个页签。
- 新增 `.nw-pane-fallback` 骨架（Tab 懒加载兜底）+ `.nw-boot` 首屏骨架（`index.html` 内联）。

### 上线后修复的致命 bug：整站白屏

`App.tsx` 把 `const renderTabPane = useCallback(...)` 写在**模块顶层**（组件之外）→
Hook 在 React 渲染上下文外执行 → `ReactCurrentDispatcher.current === null` →
启动即抛 `Cannot read properties of null (reading 'useCallback')` → `#root` 全空、整站白屏。

**当时 629 个单测全部通过却完全没抓到** —— 因为没有一条用例真正挂载 `<App />`。
修复：改为模块级普通函数（引用同样恒定，等价 `useCallback([])`）。
**并新增 `tests/app-smoke.test.ts`（2 条）**补上盲区：挂载 `<App/>` 不许抛错 + 必须渲染出内容；`MainShell` 结构含 pager/底栏/把手且把手在 nav 外。

### 门禁

`tsc` 0 error / `vitest` **67 files · 629 tests 全绿** / `vite build` 成功 / 首包 126.4 KB。

## v1.7.9（2026-11-23）· 修复左右滑动切页失效 + 滑动误触详情 + 筛选栏冗余空白

> 用户录屏实测反馈（我抽帧 40 秒视频逐帧核对确认）：

> 3. 首页「全部/在役/退役」筛选栏区域上下滑动时，**没内容也能往上滑一点**，UI 别扭。
> 另：上一轮交付的记账 skill 只落在本地、未交付/未推 GitHub，本次一并补齐。

### 修复①：左右滑动切页完全失效（根因：`touch-action: pan-y` 拦掉了横向手势）

`工程/app/src/components/ui/PullToRefresh.tsx` 内联 `touchAction: 'pan-y'`，而这个组件
**包裹着每个 pager pane 的全部内容**。`pan-y` 告诉浏览器「本区域只允许纵向平移」，
于是横向触摸手势**根本不会交给外层的原生横向滚动**（`nw-pager-track` 的
`overflow-x:auto + scroll-snap`），切页彻底失效。
**修法**：`pan-y` → `pan-x pan-y`（PullToRefresh 的下拉逻辑只在「纵向 + 已到顶」时
`preventDefault`，横向本就不归它管）。实测：触摸横滑两次，`scrollLeft` 0 → 1536 → 3072，
正常翻到「生活流」「报表」。

### 修复②：滑动被误判为点按 → 误开详情

`HomePage.tsx` 物品卡的 `onCardUp` 只判断「长按是否触发」(`pr.fired`)，
**完全不看手指是否移动过** → 横滑 200px 松手，因未到 500ms 长按，直接 `setDetailId` 开详情。
**修法**：手势状态加 `moved` 标记，`onCardMove` 位移 >10px 置 `moved=true`；
`onCardUp` 改为 `if (!pr.fired && !pr.moved) setDetailId(...)`；新增 `onCardCancel`
在原生滚动接管时也置 `moved`。实测：物品卡横滑后 `detailOpen:false`，不再误开。
长按 500ms 进编辑、单击进详情两个原有交互均保留。

### 修复③：筛选栏区域上滑冗余空白

底部避让悬浮底栏的 112px 原来做成**滚动容器自身的 `padding-bottom`**，padding 计入
`scrollHeight` → 内容不足一屏时也能向上滑出 112px 纯空白。
**修法**：改为内容流末尾的弹性占位块 `.nw-pane-gap` + `nw-pane-body` flex 列布局 +
`min-height:100%`：内容不足一屏时 gap 撑满（滚不出空白），内容超过一屏时 gap 归零
（不额外加 112px）。实测：空列表时 `scrollHeight === clientHeight`（溢出 **0**），
彻底滚不动；有 1 件物品时只剩真实内容溢出量。

上一轮 `docs/skill/SKILL_bookkeeping_v2.md`（354 行）只落本地，**未推 GitHub、未交付**。
本次：① 归档到 `工程/app/docs/skill/SKILL_bookkeeping.md`（随仓库推送，GitHub 可见）；
② 确认已覆盖 v1.8.1 全部新端点（icons/stats/entity）与三条图片匹配规则。

### v1.7.8 上线后补丁（同日）· 云端图签名 + 本地瘦身

上线后发现三个连带问题，均已修复并二次部署：

1. **云端图全部 401（白块）** —— 根因是 `index.php` 的读图路由正则
   `^/api/user/images/([^/]+)$` **把 `sign`/`list`/`gc` 也当成了 sha**，
   导致签名接口 `/api/user/images/sign` 根本没被调用，直接进 `send()` 返回 `bad sha256`。
   前端因此**拿不到任何签名 URL**，所有云端图走裸路径 → 401。
   修法：正则排除 `sign`/`list`/`gc` 三个保留字。实测签名接口 `ok:true`、签名 URL 取图 `200 / image/jpeg`。

2. **PhotoImg 显式签名** —— 之前依赖 `renderUrlFor()`（缓存未命中返回裸路径 + 后台重签），
   但组件不会因后台重签完成而重渲染，`<img>` 拿着裸路径吃 401、永久白块。
   改为 `await signCloudUrl(sha)` 后再渲染，签名就绪前不挂 `<img>`。
   新增 `imageCloud.signCloudUrl()`（可 await 的签名入口）。

3. **图标缓存不该缓存云图** —— `iconCacheStore` 会把 `/api/user/images/<sha>` 的字节
   也存进 KV（每条 30~180KB），26 张图又把 localStorage 撑回 ~1.9MB，抵消了「图片上云」的瘦身。
   修法：`iconCacheStore` 直接跳过云端 URL（服务端已给 `immutable` 强缓存）；
   新增 `purgeCloudIconCache()` 在冷启动跑一次，清掉历史遗留条目。

**最终实测**：localStorage **1,946KB → 80KB**（省 96%）；首页 **17/17 张图全部加载**（零坏图）；
带签名图片 14/14；云端引用 26 条、本地 base64 **0 条**；12 个路由零崩溃。

**上线过程中的一次服务器故障（非本项目代码问题）**：部署期间服务器（990MB / 2 核）
内存耗尽、PHP-FPM 子进程被 OOM Kill，load average 一度飙到 51、站点无响应约 8 分钟，
自行恢复。详见 `docs/30-环境.md` 的内存告警记录。

## v1.7.7（2026-11-22）· 崩溃修复 + 图片云端化

> 用户报告：用外部 Agent 调 AI API 批量导入带图物品后，**App 与网页端同时崩溃**（`Cannot read properties of undefined (reading 'length')`），且存储从 600K 暴涨到 1.8MB 造成卡顿。

### 根因（实地取证，非推测）

从线上 localStorage 取出 19 件物品：**11 条来自 AI API 导入**的缺 `extraFees`/`tags`/`incomes` 三个字段、图片是**裸 base64（无 `data:` 前缀）**；8 条正常表单的字段齐全。

三层根因：
1. **崩溃点** `HomePage.tsx` 裸访问 `detail.extraFees.length`。服务端早有加固逻辑（`normalizeBackupPayload`），但**只覆盖备份/同步三条路径，AI 写入完全没走过**。
2. **图片不显示**：`goodsIconValue()` 靠 `ref.startsWith('data:')` 判本地图，裸 base64 判不出 → 返回空串。
3. **存储膨胀**：图片 base64 全量内嵌 localStorage + 每次备份上传完整快照（实测 1,603 KB）。

> React #300 是伴生现象（一次导入触发多次边界捕获 + store 批量写入），不是独立缺陷。

### 修复

**服务端**：新建 `EntityNormalize.php`，把实体级加固抽成公共函数覆盖 **12 个集合**，接入 AI 写入 + AI 读取 + 备份/同步**全部路径**；图片归一化把 10 种输入收敛成前端唯一认的 `{source, ref}`（裸 base64 按魔数识别 jpeg/png/gif/webp）；图片上限 2MB，超限拒绝并返回 warning。

**前端**：崩溃点补 `?.`；全项目扫描补齐约 20 处裸访问（`currency` 9 处、`status` 5 处、`date`/`tags`/`reasons` 等）；`goodsIconValue()` 识别裸 base64 自动补前缀；`aiInboxMerge` 对四条合并入口做 schema 兜底；存储配额不足时明确 toast 提示。

**图片云端化**（用户明确要求）：内容寻址存储 `storage/images/<ownerHash>/<sha前2位>/<sha>.<ext>`；新增 `/api/user/images`（上传/去重）、`/list`（差异比对）、`/sign`（重签）、`/gc`（回收）、`GET /api/user/images/<sha>?t=&s=`（签名读取，ETag + immutable 强缓存）；前端记录只存 `{source:'cloud', ref, sha256, thumb}`，`thumb` 是 4KB 缩略图保证离线可见。存量 base64 完全不动，离线/未登录自动短路。

### 修复过程中引入并修掉的回归（重要教训）

首次上线后**备份里所有物品图片变成 `{"source":"system","ref":"📦"}`**。原因：`EntityNormalize` 不认识云端引用 `/api/user/images/<sha>` → 当成无效值 → 回落 system emoji。这是**两个 Worker 并行造成的接口断裂**（云端化新增 `cloud` 形态，归一化层不认识）。已补 `looksCloudRef()` / `cloudFromString()`，并加 22 项回归测试。

### 实测效果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| localStorage | 2,061 KB | **178 KB**（省 91%） |
| 备份 payload | 1,603 KB | **43 KB**（省 97%） |
| 本地 base64 图片 | 23 条 | **0 条** |
| 云端图片引用 | 0 条 | **27 条** |

崩溃验证：13 件脏物品逐一打开详情**零崩溃**；首页 14 张图全部加载成功；刷新后图片仍正常；10 个页面全量走查零崩溃。门禁：tsc 0 error / vitest **623 passed** / build 成功。

### 关键设计：为什么需要「云端待入账」

纳物是**本地优先**，服务端只存整份快照（`flyme_backups`）。若 AI 直接改快照，
客户端下一次自动备份会把整份覆盖回去，AI 记的账就丢了。因此：
1. AI 的记录先进 `flyme_ai_events`（待入账箱），并立即合并进最新快照；
2. 客户端推新快照（`/api/sync/push`）时，服务端**自动再合并一次**，保证不被冲掉；
3. 客户端可用 `/api/ai/inbox` 增量拉取并合并（网页/App 的「合并」按钮），无需整份恢复。

### 安全

- API Key 存服务端设置表的一次性映射（明文不入库），可随时撤销，撤销后立即 401；
- 所有查询/写入按 owner 隔离，一把 Key 只能动自己账号的数据；
- 首把 Key 支持「一次性引导文件」（`storage/.ai-bootstrap`，用后自删），不留常驻后门。

### 1. 光标 Bug 修复（P0）

用户复现：输入一段文字 → 光标点到文字中间 → 删一个字或打一个字 → 光标立刻跳到整句末尾，
后续输入全部落在句尾，改一个数字等于重打一遍。

根因是**两层叠加**，只修一层都会复发：

| 层 | 成因 | 修复 |
|---|---|---|
| 原生 | `capacitor.config.ts` 的 `android.captureInput: true`：Capacitor 用自己 new 的 `BaseInputConnection` 顶掉 Chromium 的 `WebViewInputConnection`。前者是硬键盘用的简化实现，不管输入法组合区（composing region）——`deleteSurroundingText`（删一个字）退化成「整段重设文本」，`commitText` 也把 selection 顶到末尾 | 改回 Capacitor 默认 `false`（本项目无硬键盘捕获需求），交还原生输入连接 |
| JS | 「对话记一笔」输入框每次 `input` 都改 `style.height`（自适应高度）来撑高，Android WebView 在组合期重排选区，光标被甩到末尾 | 新增 `src/lib/caretGuard.ts`：**先读 selectionStart/End → 再动 DOM → 立刻恢复 → `requestAnimationFrame` 下一帧再确认一次**；单行输入（最高频路径）只做只读测量，**完全不动样式** |

- 输入框保持**非受控**（`defaultValue`），不允许因改值重挂载整个输入框 DOM
- `caretGuard.ts` 文件头写了「禁止删除」的护栏说明，并配 `tests/caret-guard.test.ts` 源码断言：
